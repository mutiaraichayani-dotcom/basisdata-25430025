## Titik Analisis

### 1. Apa tujuan pengujian tersebut?
Pengujian memastikan database menerima data yang sesuai aturan dan menolak data yang melanggar aturan. Pengujian mencakup validasi anggota, keunikan nomor nota dan NIM, batas stok dan jumlah barang, foreign key, serta keamanan perintah UPDATE.

### 2. Mengapa hasil harus dicatat berdasarkan tampilan phpMyAdmin?
Tampilan phpMyAdmin menjadi bukti bahwa perintah benar-benar dijalankan. Hasil aktual dapat dibandingkan dengan hasil yang diharapkan untuk menentukan status setiap skenario.

### 3. Satu uji yang diperkirakan GAGAL karena aturan bisnis belum dijaga server
Contohnya adalah penjualan dengan `qty` lebih besar daripada stok yang tersedia. Transaksi seperti ini dapat diterima jika database hanya memeriksa bahwa `qty` lebih dari nol, tetapi tidak memeriksa apakah stok mencukupi.

CHECK constraint pada tabel `barang` hanya memeriksa nilai pada baris tabel `barang`, misalnya memastikan stok tidak negatif. CHECK tersebut tidak otomatis membandingkan `qty` pada tabel `detail_penjualan` dengan stok pada tabel `barang`. Aturan tersebut perlu dijaga melalui transaksi yang memeriksa dan mengurangi stok secara konsisten, trigger, atau logika aplikasi/prosedur sebelum transaksi disimpan.

## Catatan Pengujian Safe Update

Pada percobaan awal, perintah berikut sempat berhasil dan mengubah harga lima baris barang:

```sql
UPDATE barang
SET harga_jual_barang = harga_jual_barang + 100;
```

Setelah mode aman dipastikan aktif, pengujian ulang menggunakan:

```sql
SET SESSION sql_safe_updates = 1;

UPDATE barang
SET harga_jual_barang = harga_jual_barang;
```

Perintah pengujian ulang ditolak dengan ERROR 1175 sehingga UJ-08 dinyatakan LULUS. Perhatikan bahwa percobaan awal telah menaikkan harga lima barang sebesar 100. Periksa harga barang jika ingin memastikan data akhir sesuai catatan praktikum.

## Kesimpulan

Berdasarkan konfirmasi hasil delapan skenario, seluruh pengujian dinyatakan LULUS karena hasilnya sesuai harapan Tabel 6.1. Pengujian menunjukkan bahwa CHECK, UNIQUE, FOREIGN KEY, dan safe update membantu menjaga konsistensi data. Aturan bisnis lintas tabel seperti memastikan jumlah penjualan tidak melebihi stok tetap memerlukan logika tambahan.
